## 二、為什麼分成兩份資料集

這是整個 Sprint 4 最重要的一件事，也是最容易被跳過的一件事。

| 資料集 | 筆數 | 用途 |
|---|---|---|
| `dev`（`backend/evaluation/dataset.json`） | 40 | 做 Error Analysis、據此修改 prompt |
| `holdout`（`backend/evaluation/holdout.json`） | 21 | **只量測，從不拿來改 prompt** |

v2 的 prompt 是**看著 v1 在 dev 上犯的錯**寫出來的。
它在 dev 上拿到 100%，但那個數字沒有意義 —— 等於對著考卷改答案。

只有 holdout 上的數字能回答「拿去給真實客戶用會怎樣」。
所以上面那張表引用的是 holdout，不是 100% 那個好看的數字。

兩份資料集都不是用 LLM 生成的。
若用同一個模型出題又拿它作答，量到的只是它的自我一致性，不是準確率。

## 三、Prompt v1 → v2 的效果

| | dev（調過的） | holdout（沒調過的） |
|---|---|---|
| v1 欄位正確率 | 97.8% | 98.6% |
| v2 欄位正確率 | 100% | **99.5%** |
| v1 完全正確率 | 80.0% | 85.7% |
| v2 完全正確率 | 100% | **95.2%** |
| v1 捏造率 | 1.6% | 0.8% |
| v2 捏造率 | 0% | **0%** |

**改善在 holdout 上也成立，代表這不只是過擬合。**
但幅度明顯小很多（dev 進步 20 個百分點，holdout 只進步 9.5 個），
這個落差本身就是「dev 上的分數被高估了多少」的估計值。

### v2 改了什麼

v1 的 40 筆裡有 9 筆出錯，其中 **7 筆集中在 `location`**：

- 把「捷運附近」「學區附近」「郊區」當成區域填進去（捏造）
- 把「淡水海景」整串填進去，沒有只取地名（抽錯）
- 把「內湖或南港」整串塞進單一欄位（抽錯）

追究原因，v1 的 prompt 只寫了「保留客戶原話」，卻**沒有定義什麼才算區域**。
規則在標註標準裡有，只是沒被寫進 prompt。這不是模型笨，是我們沒講清楚。

v2 補上了「什麼算地名／什麼不算／多個區域取先講的／去掉附加描述」四條，
`location` 的 precision 從 69.6% 拉到 100%。

### 代價

v2 的 prompt 較長，每筆從 926 token 增加到 1,480 token（+60%）。
以這個用量規模，換到「捏造率歸零」是划算的 ——
CRM 裡出現客戶從沒說過的資訊，代價遠高於多付的那點 token 費。

## 四、模型比較（都在 holdout + v2）

| 模型 | 欄位正確率 | 完全正確率 | 捏造率 | 延遲中位數 |
|---|---|---|---|---|
| gpt-5.4-nano | 97.6% | 76.2% | 2.3% | 957 ms |
| **gpt-5.4-mini** | **99.5%** | **95.2%** | **0%** | **863 ms** |
| gpt-5.4 | 99.5% | 95.2% | 0% | 1,225 ms |

**結論：mini 是甜蜜點。**

往下換 nano 省錢，但完全正確率掉了 19 個百分點，而且捏造率從 0 變成 2.3% ——
那正是最不能妥協的指標。

往上換 gpt-5.4 一分錢都買不到準確率（兩者結果完全相同），延遲反而多 42%。
這個結論只在「任務結構清楚 + strict schema 約束輸出」的前提下成立：
題目本身不需要更強的推理能力，貴的模型無處施展。

> 這也是把型號寫成環境變數 `OPENAI_MODEL` 的回報 ——
> 換模型跑一次評估不用改任何一行程式碼。

## 五、目前剩下的唯一錯誤

v2 在 holdout 上只錯一筆，而且錯得很有代表性：

> hold-010「一年半內要買，預算 2000 萬到 2400 萬，三房電梯大樓，內湖」
> `purchase_timeline` 應為 `18`，模型給 `null`（漏抽）

這一筆是刻意設計來測推廣能力的：v2 的 prompt 列了「這個月／三個月內／半年內／
一年內／兩年內」，就是沒列「一年半」。模型照著列舉作答，沒有推廣到沒見過的講法。

**但它的失敗方向是對的。** 遇到不確定的講法時它選擇留空，而不是猜一個數字。
漏抽只是資料變少，業務自己補得回來；捏造則是在 CRM 裡製造客戶從沒說過的資訊。
在這個系統裡，前者遠比後者可以接受。

## 六、方法上要留意的地方

**LLM 有隨機性，同一組設定兩次跑的分數不會完全一樣。**
v1 在 dev 上兩次跑分別是 97.2% 與 97.8%。差距約在半個百分點，
所以只有超過一個百分點的差異才值得當成「真的有變好」。

**樣本數不大。** holdout 只有 21 筆 × 10 欄位 = 210 個判斷。
95.2% 的完全正確率換算成筆數是「21 筆錯 1 筆」，錯 2 筆就掉到 90.5%。
引用時要一併講樣本數，不要只講百分比。

**Ground Truth 是人標的，也可能標錯。**
標註標準寫在 [PROGRESS.md](../PROGRESS.md) 第三節，
每一筆有爭議的裁決理由都記在資料集的 `note` 欄位裡。
若日後認為某筆標錯了，改的是資料集而不是 prompt。
