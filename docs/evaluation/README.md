## 二、為什麼分成兩份資料集

這是整個 Sprint 4 最重要的一件事，也是最容易被跳過的一件事。

| 資料集 | 筆數 | 用途 |
|---|---|---|
| `dev`（`backend/evaluation/dataset.json`） | 40 | 做 Error Analysis、據此修改 prompt |
| `holdout`（`backend/evaluation/holdout.json`） | 21 | **只量測，從不拿來改 prompt** |

v2 的 prompt 是**看著 v1 在 dev 上犯的錯**寫出來的。
它在 dev 上拿到 100%，但那個數字沒有意義 —— 等於對著考卷改答案。

只有 holdout 上的數字能回答「拿去給真實客戶用會怎樣」。
所以上面那張表引用的是 holdout，不是 100% 那個好看的數字。

兩份資料集都不是用 LLM 生成的。
若用同一個模型出題又拿它作答，量到的只是它的自我一致性，不是準確率。

## 三、Prompt v1 → v2 的效果

| | dev（調過的） | holdout（沒調過的） |
|---|---|---|
| v1 欄位正確率 | 97.8% | 98.6% |
| v2 欄位正確率 | 100% | **99.5%** |
| v1 完全正確率 | 80.0% | 85.7% |
| v2 完全正確率 | 100% | **95.2%** |
| v1 捏造率 | 1.6% | 0.8% |
| v2 捏造率 | 0% | **0%** |

**改善在 holdout 上也成立，代表這不只是過擬合。**
但幅度明顯小很多（dev 進步 20 個百分點，holdout 只進步 9.5 個），
這個落差本身就是「dev 上的分數被高估了多少」的估計值。

### v2 改了什麼

v1 的 40 筆裡有 9 筆出錯，其中 **7 筆集中在 `location`**：

- 把「捷運附近」「學區附近」「郊區」當成區域填進去（捏造）
- 把「淡水海景」整串填進去，沒有只取地名（抽錯）
- 把「內湖或南港」整串塞進單一欄位（抽錯）

追究原因，v1 的 prompt 只寫了「保留客戶原話」，卻**沒有定義什麼才算區域**。
規則在標註標準裡有，只是沒被寫進 prompt。這不是模型笨，是我們沒講清楚。

v2 補上了「什麼算地名／什麼不算／多個區域取先講的／去掉附加描述」四條，
`location` 的 precision 從 69.6% 拉到 100%。

### 代價

v2 的 prompt 較長，每筆從 926 token 增加到 1,480 token（+60%）。
以這個用量規模，換到「捏造率歸零」是划算的 ——
CRM 裡出現客戶從沒說過的資訊，代價遠高於多付的那點 token 費。

## 三之二、v3 → v4：新增 urgency 欄位

### 為什麼要加這個欄位

不是因為 v2 哪裡不準，而是 **Sprint 5 的 Lead Scoring 發現訊號不夠用**。

`purchase_timeline` 要有明確月數才填得進去，但真實客戶很少那樣講話。
具業務實務經驗的人出的 15 題裡，**明確月數 0 筆**——
也就是說「3 個月內購買 +20」這條計分規則在真實資料上幾乎不會觸發。

他們講的是「我下個月要過去上班，所以有點急」：有明確的急迫感，卻沒有任何月數。

所以新增 `urgency`（HIGH / LOW / null），讓 AI 判斷**語氣**，數字仍留給 Rule Engine。
這跟 `budget_is_approximate` 是同一招。

> 這是「Scoring 的需求反過來定義 AI 該抽什麼」，
> 而不是先抽一堆欄位再想能拿來做什麼。

### v3 一次就中了預期中的問題

我在動工前就預告過：急迫性比其他欄位主觀，錯誤率會比較高。結果確實如此。

| | v3 | v4 |
|---|---|---|
| urgency Recall（dev） | 54.5% | **100%** |
| urgency Recall（holdout） | 60.0% | **100%** |
| urgency 捏造（dev） | 0 | 1 |

v3 錯的 5 筆全是「漏抽」，而且是同一個病的兩種表現：

- 「三個月內想成交」→ 填了 `purchase_timeline=3`，`urgency` 卻留空（把兩欄當成互斥）
- 「還在考慮，之後再聊」「明年上半年」→ 這些字沒出現在我列的詞彙裡，就不填

**根源是 v3 給的是詞彙表，模型只認那幾個詞，不推廣。**
這跟 v2 漏掉「一年半」是同一個問題。

v4 把 urgency 那一段改成給**判斷準則**（客戶是不是表現出時間壓力），
詞彙只當例子，Recall 直接從 54.5% 拉到 100%。

代價是 dev 上多了 1 筆捏造（把 null 判成 LOW）——放寬判斷標準必然的取捨，
但 holdout 上捏造仍是 0。

### 這一輪最重要的事

**評估機制第一次當了守門員，而不只是產生數字。**

如果沒有這套機制，v3 會就這樣上線。`urgency` 有一半的訊號抓不到，
Lead Score 會安靜地算錯，而且沒有人會發現——因為分數看起來總是「合理」的。

## 四、模型比較（都在 holdout + v2）

| 模型 | 欄位正確率 | 完全正確率 | 捏造率 | 延遲中位數 |
|---|---|---|---|---|
| gpt-5.4-nano | 97.6% | 76.2% | 2.3% | 957 ms |
| **gpt-5.4-mini** | **99.5%** | **95.2%** | **0%** | **863 ms** |
| gpt-5.4 | 99.5% | 95.2% | 0% | 1,225 ms |

**結論：mini 是甜蜜點。**

往下換 nano 省錢，但完全正確率掉了 19 個百分點，而且捏造率從 0 變成 2.3% ——
那正是最不能妥協的指標。

往上換 gpt-5.4 一分錢都買不到準確率（兩者結果完全相同），延遲反而多 42%。
這個結論只在「任務結構清楚 + strict schema 約束輸出」的前提下成立：
題目本身不需要更強的推理能力，貴的模型無處施展。

> 這也是把型號寫成環境變數 `OPENAI_MODEL` 的回報 ——
> 換模型跑一次評估不用改任何一行程式碼。

## 五、剩下那一筆錯誤，在業務上其實無關緊要

v4 在 holdout 上只錯一筆，從 v2 錯到現在都是同一筆：

> hold-010「一年半內要買，預算 2000 萬到 2400 萬，三房電梯大樓，內湖」
> `purchase_timeline` 應為 `18`，模型給 `null`（漏抽）

它確實反映了一個真實的模型特徵：prompt 列了「這個月／三個月內／半年內／
一年內／兩年內」，就是沒列「一年半」，模型照著列舉作答，不推廣。
v3 的 urgency 漏抽是同一個病，v4 改用判斷準則就解決了。

**但業務上這一筆標 18 還是 null，結果一樣。**
一年半後才要買的客戶，不管月數填多少都會被排到後面 ——
業務的動作沒有任何差別。

### 這暴露了評估設計的一個盲點

「欄位正確率 99.6%」把所有欄位、所有錯誤都當成**等重**。但實際影響差很多：

| 錯誤 | 業務後果 |
|---|---|
| 預算 2000 萬抽成 200 萬 | 帶錯物件，客戶跑掉 |
| 「一年半」沒抽到月數 | 沒有後果 |

所以逐欄位那張表比總分有用，而**捏造率**又比逐欄位正確率更值得盯 ——
它直接對應「CRM 裡出現客戶從沒說過的資訊」這個真實傷害。

真要更精準，可以做業務影響加權的指標。但在樣本只有 21 筆的規模下，
加權只會讓數字更難解讀，所以目前選擇「報告等重的數字 + 文件講清楚哪些錯誤重要」。

## 六、方法上要留意的地方

**所有錯誤在指標上等重，但在業務上不是。** 見第五節。

**欄位數變過，跨版本比較要注意。**
v1、v2 是 10 個欄位；v3 之後多了 `urgency`，變成 11 個。
所以 v2 與 v4 的「完全正確率」分母不同，v4 其實是在更難的題目上拿到同樣的分數。
schema 也跟著版號走（跑 v1 就用 10 欄位的 schema），
否則「留著舊版是為了能重跑對照」這件事就破功了。

**LLM 有隨機性，同一組設定兩次跑的分數不會完全一樣。**
v1 在 dev 上兩次跑分別是 97.2% 與 97.8%。差距約在半個百分點，
所以只有超過一個百分點的差異才值得當成「真的有變好」。

**holdout 也不是完全乾淨的。**
它是在 v2 寫完之後才建立的，出題的人知道 v2 的規則長什麼樣。
標準做法應該是先切資料再調 prompt。
因此另外準備了一份**期末考資料集**（`backend/evaluation/final_test.json`），
15 題由具實際房仲業務經驗的人出題、且出題者未讀過 prompt，
鎖到 Sprint 7 上線前才第一次執行（跑它需要多打一個確認旗標）。

**樣本數換算成信賴區間會很寬。**
holdout 的完全正確率 20/21 = 95.2%，
但 95% 信賴區間是 **77.3% ~ 99.2%**（Wilson 區間），真實值可能低到 77%。
錯 1 筆是 95.2%，錯 2 筆就掉到 90.5% —— 單一筆的浮動就能讓數字跳 5 個百分點。
講數字時要一併講樣本數，不要只講百分比。

**Ground Truth 是人標的，也可能標錯。**
標註標準寫在 [PROGRESS.md](../PROGRESS.md) 第三節，
每一筆有爭議的裁決理由都記在資料集的 `note` 欄位裡。
若日後認為某筆標錯了，改的是資料集而不是 prompt。
